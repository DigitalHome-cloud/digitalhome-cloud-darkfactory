## Findings

### HIGH (6)

#### H-1. No security headers (`customHttp.yml`) on any of the three apps  *(carry-over)*

**Domain**: Frontend security
**Evidence**: `customHttp.yml` absent in `repos/{portal,designer,modeler}/`.

**Impact**: Missing CSP, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. Lack of CSP means any XSS that lands (see H-3, H-4) can exfiltrate to arbitrary external origins. The Gen 2 Cognito Hosted UI domain is different from Gen 1 — when you add the file, update the CSP `connect-src` directive.

**Remediation**: Same template as the prior audit. Add to each app:
```yaml
customHeaders:
  - pattern: '**/*'
    headers:
      - key: 'Strict-Transport-Security'
        value: 'max-age=31536000; includeSubDomains; preload'
      - key: 'X-Content-Type-Options'
        value: 'nosniff'
      - key: 'Referrer-Policy'
        value: 'strict-origin-when-cross-origin'
      - key: 'Permissions-Policy'
        value: 'camera=(), microphone=(), geolocation=()'
      - key: 'Content-Security-Policy'
        value: "default-src 'self'; img-src 'self' data: https://*.amazonaws.com; script-src 'self' 'unsafe-inline'; connect-src 'self' https://4eqtuivn7rggzd32hleoxeycv4.appsync-api.eu-central-1.amazonaws.com https://cognito-idp.eu-central-1.amazonaws.com https://amplify-digitalhomecloudd-dhcstoragebucket676c6b9f-nwmeen76q2dv.s3.eu-central-1.amazonaws.com; style-src 'self' 'unsafe-inline'; font-src 'self' data:;"
```

#### H-3. Portal blog posts render raw HTML via `dangerouslySetInnerHTML`  *(carry-over)*

**Domain**: Frontend security
**Evidence**: `repos/portal/src/templates/blog-post.js:23`

```jsx
<div className="dhc-text-section" dangerouslySetInnerHTML={{ __html: post.html }} />
```

**Impact**: Same as 2026-05-07 — gatsby-transformer-remark doesn't sanitize; raw HTML in markdown executes in user browsers. Acceptable today because branch protection (C-4 ✅) gates blog post commits, but defense-in-depth is still missing.

**Remediation**: Wrap with `DOMPurify.sanitize()` or migrate the template to MDX. Same fix as 2026-05-07.

---

#### H-4. Designer's drawing page renders generated SVG via `dangerouslySetInnerHTML`  *(carry-over)*

**Domain**: Frontend security
**Evidence**: `repos/designer/src/pages/drawing.js:117`

**Impact**: SVG `<text>` nodes embed user-controlled strings (room names, device labels) from the SmartHomeDesign data. Even though C-2 v2 now mediates writes through the signed-URL Lambda (so an attacker can't directly tamper with someone else's design), an owner can still inject HTML/SVG into their OWN data and the rendering of that data in the browser will execute it. With multi-owner support (C-2 v2), one compromised owner can inject for another. Same XSS risk as the prior audit.

**Remediation**: `DOMPurify.sanitize(svg, { USE_PROFILES: { svg: true, svgFilters: true } })` before injection. Or rebuild the SVG via React JSX so React's escaping does the work.

#### M-6. **NEW**: DynamoDB tables have no Point-in-Time Recovery (PITR) enabled

**Domain**: Data layer
**Evidence**: `aws dynamodb describe-continuous-backups --table-name UserProfile-...-NONE` returns empty PITR status.

**Impact**: If a table is accidentally truncated (e.g. operator error, rogue script, schema-deploy bug that drops a table), there's no rollback. Affects all 4 Gen 2 tables: `UserProfile`, `LibraryItem`, `SmartHome`, `SmartHomeDesign`. Pre-launch this is acceptable; before real users, enable.

**Remediation**: Per table:
```bash
aws dynamodb update-continuous-backups \
  --table-name <table> \
  --point-in-time-recovery-specification PointInTimeRecoveryEnabled=true
```
Or in Gen 2 declaratively, override via CDK in `amplify/backend.ts`:
```ts
import { CfnTable } from "aws-cdk-lib/aws-dynamodb";
for (const tableName of ["UserProfile", "LibraryItem", "SmartHome", "SmartHomeDesign"] as const) {
  const table = backend.data.resources.tables[tableName];
  (table.node.defaultChild as CfnTable).pointInTimeRecoverySpecification = {
    pointInTimeRecoveryEnabled: true,
  };
}
```

### INFO (6)

#### I-1. Gen 2 backend code lives in TypeScript, fully tracked in git  *(architectural improvement)*

The umbrella's `amplify/backend.ts`, `amplify/data/resource.ts`, `amplify/auth/resource.ts`, `amplify/storage/resource.ts`, and `amplify/functions/*/{resource,handler}.ts` are all tracked. Schema changes are now reviewable via standard PR diff. This was H-8 in the prior audit — closed by the migration architecture.

#### I-2. Custom mutations port intact

`requestDesignReadUrl` / `requestDesignWriteUrl` are now `a.handler.function(dhcDesignStorageProxy)`-backed mutations. The `@function` directive footgun (Gen 1 required matching the function name with `${env}` interpolation) is replaced by direct TypeScript imports — no string-matching at deploy time.

#### I-3. CDK escape hatches in `amplify/backend.ts` cleanly grant cross-resource IAM

Two patterns demonstrated:
- `proxyLambda.addToRolePolicy(new PolicyStatement(...))` for S3 + DDB grants (via `backend.storage.resources.bucket.bucketArn` and `backend.data.resources.tables.SmartHomeDesign.tableArn` references)
- `userPoolWildcardArn` constructed from `Stack.of(...).region/account` to avoid the circular-dependency footgun on the Cognito trigger

Both are textbook Gen 2 patterns. Future Lambdas needing cross-resource IAM should follow the same shape.

#### I-4. `defineStorage()` correctly omits the `tenant/*` prefix

Default-deny is the security boundary — no auth or guest role gets IAM access to that prefix. The dhcDesignStorageProxy Lambda is the only path. Confirmed by reading the source and the comment block.

#### I-5. AWS account / IAM observations

The `dlab5_devops` IAM user can list Cognito User Pools and DDB tables, but cannot list AppSync APIs (`AccessDeniedException` on `appsync:ListGraphqlApis`) or read S3 bucket public-access blocks (`s3:GetBucketPublicAccessBlock`). For ongoing operations + future audits, consider granting:
- `appsync:Get*`, `appsync:List*` on `arn:aws:appsync:eu-central-1:*:apis/*`
- `s3:GetBucketPolicy`, `s3:GetBucketPublicAccessBlock`, `s3:GetEncryptionConfiguration` on the platform's buckets
This is also why this audit had a few "could not verify" entries.

#### I-6. Gen 1 fully decommissioned

All Gen 1 CloudFormation stacks (`amplify-digitalhomecloudback-...-main`, `amplify-digitalhomecloudback-staging-bf2cf`) deleted. No legacy User Pool, S3 bucket, AppSync API, DDB tables, or Lambdas remain. Cost: now paying for a single backend stack instead of two.
